Why bad PDF redactions happen (and how to spot them)

A black box over text in a PDF is not a lock. Failed redactions in public records are a well-documented problem: text that appears permanently covered can often be copied, searched, or extracted straight out of the file. This guide explains why redaction fails, how to check your own PDFs before you share them, and what to do when a record you receive arrives badly redacted.

The black-box illusion

When someone "redacts" a PDF by drawing a black rectangle over text, the text underneath usually stays in the file. It is like putting a sticky note over a sentence in a printed book — the words are still there, just covered. A PDF is a container that stores text, images, and fonts as data, and covering content is not the same as removing it. Any tool that can read the underlying content layer can often still find the original words, no matter how solid the black box looks on screen.

A redaction is only real when the underlying content is gone from the file — not when it's merely covered up. If you can copy it, it isn't redacted.

Why redaction fails

Failures come in a few recurring flavors.

Drawing boxes instead of removing content

The most common failure by far. Some editors' "redaction" features simply paint a rectangle over the page, leaving the text layer untouched. Search, copy, and text-extraction tools read right through it.

Re-encoding artifacts

Even when text is genuinely deleted, re-encoding can leave fragments behind. PDFs saved incrementally keep old versions of pages in the file, and deleted objects can linger where repair tools can resurrect them.

Metadata leaks

Author names, email addresses, software names, and the original document title often survive in the PDF's metadata — invisible in normal viewing but readable in file properties or any metadata tool. This is a classic, easy-to-miss leak.

Hidden layers

Layers, annotations, comments, and "invisible" text set in white or zero-size fonts can all carry content that never appears on screen — but is still part of the file.

How to check your own redacted PDFs

Run all three checks before you share anything.

The copy-paste test

Open the PDF, select the area where the black box is, and copy. Paste into a text editor. If the hidden text appears, the redaction failed. This test catches most bad redactions.

Extract the text

Pull every scrap of text out of the file and search the output for names, addresses, and anything else you meant to hide. Free options include pdftotext (part of the Poppler tools) on the command line, or any PDF reader's search function.

Check the metadata

Open the file's properties (File → Properties, or Details in your OS) and look at the author, title, keywords, and comments fields. If anything sensitive appears there, it is still in the file — and it will travel with every copy.

How to redact properly

Use a real redaction tool, not a drawing tool. Proper redaction removes the underlying content permanently rather than covering it up. Adobe Acrobat's Redact tool (with "remove hidden information" enabled) and dedicated open-source redaction tools do this correctly. Redact a copy, keep your original intact, and always verify with the three checks above before sharing. When in doubt, don't send the file at all.

What to do if you receive a badly redacted public record

First, document the finding: save a copy and note the date and what you were able to recover, before the agency can pull or "fix" the file. Treat the leak as real — the information is now in the record you hold. Report the failure to the agency's records-access officer — they need to know their redaction process is broken. You are not obligated to publish what you found; documenting it protects you and everyone else. If you see the same failure across multiple records, that is a systemic privacy problem worth raising with oversight bodies.
